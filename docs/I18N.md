# Internationalisation (v1.8.0)

Per-device language preference; bridge auto-detects host locale.
Currently planned languages: `en` (default), `zh-CN`, `ja`.

## Approach

All user-facing strings live in `main/i18n/strings_<lang>.h` as a
`const char* const strings_<lang>[I18N_COUNT]` table indexed by
`i18n_key_t` enum (declared in `main/i18n/strings.h`).

`i18n_get(I18N_KEY)` returns the active-language pointer:

```c
lv_label_set_text(label, i18n_get(I18N_IDLE_NO_SESSIONS));
```

The active language switches via `dash config '{"locale":"zh-CN"}'`
+ NVS-persisted, or via the bridge's auto-detected host locale on
connect (the bridge sends `dash config locale=...` if the device's
current value differs from the host's).

## Coverage

v1.8.0 ships `en` complete + `zh-CN` and `ja` at 80% coverage (the
common scenes — idle, sessions, prompt, tokens, status — plus the
permission dialog). Missing strings fall back to `en`.

## Extraction tool

`tools/i18n/extract.py` greps the firmware sources for
`i18n_get(I18N_*)` calls and emits a checklist of keys vs. each
language file. Run pre-release to catch missing translations.

## Font handling

Fraunces + Plex Mono (brand fonts) don't cover CJK. v1.8.0 adds a
fallback chain: LVGL renders CJK via a CJK font (Noto Sans CJK
Light) included as a compressed bin in the OTA partition (~3.5 MB).
Loaded lazily on first non-Latin character.

## Scaffold status

Spec + `main/i18n/strings.h` + `strings_en.h` ship in v1.8.0.
Translations (`strings_zh.h`, `strings_ja.h`) + extract tool +
CJK font integration land in v1.8.x. Requires COMM2 (community
gen-2 agent for translations) in a future cycle.
