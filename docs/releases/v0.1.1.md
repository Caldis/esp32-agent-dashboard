## Firmware ([`main/`](../../main/))

### Multi-agent state model

```c
// main/agent_state.h
#define AGENT_SLOT_MAX 4
```

- Up to **4** concurrent agents. Identity keyed on
  `(kind, session_id)`, so left/right placement is stable
  frame-over-frame and users can track an agent by muscle memory.
- Rolling per-agent transcript window (5 entries), spark history
  (32 samples), and cumulative/today token counters.
- Per-device config slot (`device_name`, `owner`, `theme`,
  `default_scene`) populated by `dash config`.

### Theme system ([`main/theme.c`](../../main/theme.c) / [`main/theme.h`](../../main/theme.h))

- Three named palettes — `noir` / `lab` / `mono` — each with `bg`,
  `surface`, `text`, `text_dim`, `accent_claude`, `accent_codex`,
  `accent_other`, `warning`, `danger`, `success`.
- `theme_set_by_name("...")` flips one `.rodata` pointer. No alloc,
  atomic-enough on Xtensa for the redraw cadence.
- `theme_accent_for_kind("claude-code")` → rust;
  `theme_accent_for_kind("codex")` → teal. The same hex codes live in
  [`docs/brand/palette.md`](../../docs/brand/palette.md) so brand and firmware never drift.

### New `scene_dashboard`

[`main/scenes/scene_dashboard.c`](../../main/scenes/scene_dashboard.c) is now the **default scene at
boot**. One screen, both agents side-by-side, header strip with
`device_name` + a stale indicator when connection age > 30 s, bottom
aggregate sparkline + running/waiting counters.

### Other firmware changes

- Tool icons ([`main/tool_icons.c`](../../main/tool_icons.c)) — Font-Awesome glyphs for
  `Bash` / `Edit` / `Read` / `Grep` / `Write` / … on every transcript
  row.
- Heap watchdog ([`main/esp32_agent_dashboard_main.c`](../../main/esp32_agent_dashboard_main.c)) — emits
  `EVT: low_heap` before the device actually OOMs.
- `sdkconfig.defaults` — extra LVGL fonts for the wider scene set.

## Host bridge ([`tools/claude_buddy_bridge.py`](../../tools/claude_buddy_bridge.py))

### Pluggable transport

```bash
# Real device
python tools/claude_buddy_bridge.py serve --port-kind serial --port COM9

# Mock device (CI, offline iteration)
python tools/claude_buddy_bridge.py serve --port-kind tcp --port 127.0.0.1:9876
```

The bridge no longer shells out to `esp-harness console --cmd` per
push (that was the G-1 latency floor). It holds a persistent transport
handle for both modes, with an open-with-retry loop (30 s window, 2 s
cadence) and an `on_reconnect` callback that re-pushes the last
buffered snapshot.

### `~/.claude-buddy/config.toml`

Auto-created on first run from
[`tools/config.toml.example`](../../tools/config.toml.example). 11 flags exposed on every
subcommand:

```text
--throttle-ms / --keepalive-ms / --permission-timeout-s
--device-name / --owner / --theme {noir,lab,mono}
--port-kind {serial,tcp} / --port / --listen
--health-poll-s / --dry-run
```

CLI **always** wins over `config.toml`; `config.toml` wins over hard
defaults.

### New subcommands

```bash
# One-shot dash health dump
python tools/claude_buddy_bridge.py status

# N-event synthetic replay; reports median / p95 / p99 push latency
python tools/claude_buddy_bridge.py bench --events 1000
```

### Multi-agent `SessionRegistry`

Keyed by `(agent_kind, session_id)`. Codex and Claude Code are
first-class peers; no implicit "default" agent kind on the wire. The
snapshot composer emits the protocol-v1 `agents:[...]` shape with
totals aggregated across slots.

### Defensive plumbing

- Snapshot publisher catches every exception, logs, never crashes the
  host (which would take down the user's CC session).
- `WIRE_MAX_BYTES = 900` ceiling on snapshot serialisation; oldest
  transcript entries truncated first.
- Reboot detection — device sends `EVT: ready` twice → bridge
  re-pushes `dash config` / `dash time` / `dash health`.

## Gaps surfaced this cycle

- **G-D1**, **G-D2** — non-blocking; tracked in [`HARNESS_GAPS.md`](../../HARNESS_GAPS.md).
  (G-D2 is resolved as of the v1 bridge's `--port-kind tcp` mode.)
- **G-H1** — bridge needs a `PayloadFollowsReader` helper from
  `esp-harness` so consumers stop reinventing the
  `TAG_BEGIN` / `TAG_END` state machine.
- **G-H2** — H1 re-implemented the G-7 tokeniser by hand and got it
  wrong on the first try (terminated at whitespace instead of
  `"`-followed-by-whitespace). Root cause: not knowing
  `esp_harness.core.parser` existed. Closed upstream test-corpus side
  by `esp-harness@85770d8` adding whitespace-inside-JSON-string
  parity cases.
- **G-H3** — bridge should **log** ERR replies from the device.
  Silently swallowing them turned a "10/10 successful" log into a
  0/10 real-world success rate during H1's debugging.
- **G-F1a** (resolved in [`9a1a13d`](https://github.com/Caldis/esp32-agent-dashboard/commit/9a1a13d)) — `tiny_json::skip_value`
  mis-balanced nested `{}` inside `[]`, silently degrading every v1
  two-agent snapshot to the v0 single-agent fallback. One-line fix in
  [`main/tiny_json.c`](../../main/tiny_json.c). `v0` never tripped it because `entries[]`
  was always top-level.
- **G-F1b** — `?dump` hard-caps at 128×128 regardless of `w=N`,
  masking the right pane of every dual-pane scene capture. Open
  against aurora-harness; flagged for the `v0.2.0` G2 cycle.

See [`HARNESS_GAPS.md`](../../HARNESS_GAPS.md) and [`CHANGELOG.md`](../../CHANGELOG.md) for the full
picture.
