# v1.0.0 RC checklist

The first stable-API release. After v1.0.0, breaking changes require a
major bump and a deprecation cycle.

This checklist is what blocks tagging v1.0.0. Items checked off as
each prior version lands.

## API stability

- [ ] PROTOCOL.md v1 frozen. v2 (transports) optional add-on, not a
      replacement.
- [ ] `dash` verb surface stable: snapshot, prompt, event, tokens,
      idle, config, time, health. No new mandatory verbs in v1.0.0.
- [ ] `~/.claude-buddy/config.toml` schema declared stable. Keys can
      be added; existing keys cannot change meaning.
- [ ] `esp_harness.core.parser` API surface stable (`tokenise_console_line`,
      `MAX_ARGS`, `MAX_LINE`, `PayloadFollowsReader`).
- [ ] `esp_harness.core.console_session.ConsoleSession` API surface
      stable (open / close / write_line / iter_replies / on_err).
- [ ] Firmware HAL: `transport_t` interface declared experimental
      until v1.0.x.

## Quality gates

- [ ] All `tools/release.ps1` gates green for the v1.0.0-rc1 build
      AND a re-run on master at v1.0.0 tag.
- [ ] esp-harness pytest: ≥ 50 tests, 100% pass rate.
- [ ] Stress 5/5 PASS against both `docs/mock_device.py` and
      `tools/mock_device_v1.py`.
- [ ] Bridge bench: ≥ 500 events/s in dry-run; ≥ 100 events/s with
      real TCP mock loopback.
- [ ] Firmware boot-to-idle-scene: ≤ 2 s on cold start.
- [ ] One 8-hour soak test (bridge running, fake-event generator
      pushing 1 event/s) without OOM or fps drop > 10%.

## Documentation

- [ ] README.md final pass. No "TODO". No "experimental".
- [ ] CHANGELOG.md has stanzas for every v0.x release.
- [ ] PROTOCOL.md exhaustively documents every `dash` verb.
- [ ] All HARNESS_GAPS marked RESOLVED, DEFERRED, or OUT-OF-SCOPE.
      No `(pending)` left.
- [ ] docs/SECURITY.md + docs/THREAT_MODEL.md reviewed.
- [ ] docs/HARDWARE_GUIDE.md tested end-to-end by a fresh reader.
- [ ] All scene PNGs in docs/img/ regenerated from the v1.0.0
      firmware.

## Community

- [ ] LICENSE.md is MIT (already done).
- [ ] CONTRIBUTING.md updated.
- [ ] Issue templates work.
- [ ] PR template works.
- [ ] CI green for ≥ 7 days continuously.
- [ ] At least one external contribution merged (community-driven
      proof-point — even a typo fix counts).

## Marketing

- [ ] Hero PNG regenerated from v1.0.0 device shot.
- [ ] Brand social-card has v1.0.0 stamp.
- [ ] HN-ready summary written (in `docs/blog/`).
- [ ] Demo video shot + uploaded (60-90s).
- [ ] Show HN post drafted.

## Backstop

If any check fails at tag-time, the version is `v1.0.0-rc<n+1>`
not `v1.0.0`. We don't ship a soft v1.0.

## Process

1. Ship every prior v0.x version with its gates green.
2. After v0.9.0 ships, run this checklist top to bottom.
3. Any unchecked item → file an issue + assign to the relevant agent
   role from `docs/AGENT_ROLES.md`.
4. When all checked, tag `v1.0.0-rc1`. Soak for 24h on a real device.
5. If no regressions, retag as `v1.0.0`. Publish.
