# v0.1.0 — Initial public release

**Released:** 2026-05-23
**Tag:** [`v0.1.0`](https://github.com/Caldis/esp32-agent-dashboard/releases/tag/v0.1.0)
**Commit:** [`1d1c3d5`](https://github.com/Caldis/esp32-agent-dashboard/commit/1d1c3d5)

The first public cut of `esp32-agent-dashboard`. A multi-agent
USB-Serial dashboard for Claude Code and Codex CLI, running on the
Waveshare ESP32-S3-Touch-AMOLED-2.16 (466×466 AMOLED).

This release is the open-source scaffolding around an already-working
device. The firmware came up in commit [`15638ca`](https://github.com/Caldis/esp32-agent-dashboard/commit/15638ca)
("v0: dashboard live on device — 5 scenes rendering, bridge dry-run
OK, G-7 closed"); `v0.1.0` itself is the README, license, contributing
guide, CI, and homepage that make it shippable.

## What's in the box

### Firmware ([`main/`](../../main/))

Five LVGL scenes registered through esp-harness's scene framework:

- `scene_idle` — pulse + "zZz" + dim ring while no agent is active
- `scene_sessions` — per-agent rows with status pip, cwd, last 3-5
  transcript entries, totals header
- `scene_prompt` — full-screen permission prompt with tool name,
  command preview, **BOOT** = approve / **USER** = deny / 60 s timeout
- `scene_tokens` — cumulative + today's tokens with a 24 h sparkline
- `scene_status` — battery / heap / uptime / build info

The device exposes a `dash` verb on the esp-harness console:

```text
dash snapshot <json>   # periodic state push (≤ 1 per 250 ms)
dash prompt   <json>   # open the prompt scene + wait for a button
dash event    <json>   # append a transcript line / change scene
dash tokens   <json>   # update cumulative + today counters
dash idle              # return to the idle scene
```

Button events come back over the same console as
`EVT: permission id=<req_id> decision=<once|deny>`.

### Host bridge ([`tools/`](../../tools/))

- [`claude_buddy_bridge.py`](../../tools/claude_buddy_bridge.py) — long-running daemon. Listens on
  TCP `127.0.0.1:7321` for hook events, maintains a `SessionRegistry`
  keyed by `(agent_kind, session_id)`, and pushes throttled snapshots
  to the device (250 ms minimum interval, 10 s keepalive). Permission
  round-trips run through a persistent
  `esp_harness.core.console_session.ConsoleSession`.
- [`hook_dispatch.py`](../../tools/hook_dispatch.py) — short-lived. Invoked by Claude Code via
  `~/.claude/settings.json` hooks. Forwards each event to the bridge,
  blocks on the reply when a `PreToolUse` event needs a permission
  decision, exits cleanly otherwise.
- [`codex_wrapper.py`](../../tools/codex_wrapper.py) — short-lived. Wraps `codex exec ...`, parses
  its JSONL stdout, forwards normalised events to the bridge. Required
  because Codex CLI has no native hook system (see
  [`HARNESS_GAPS.md`](../../HARNESS_GAPS.md) G-5).
- [`sample_session.jsonl`](../../tools/sample_session.jsonl) — canned event stream used by CI and
  offline iteration.

### Wire protocol ([`PROTOCOL.md`](../../PROTOCOL.md))

- `v1` — per-agent sessions, richer scene data, device-side config.
  This is the shape the bridge speaks today.
- `v0` — pre-release internal, single-agent. Not shipped publicly.

### Tooling

- [`docs/mock_device.py`](../../docs/mock_device.py) — TCP stand-in for the firmware. Mirrors
  `console_protocol.c`'s tokeniser exactly, so anything that talks to
  the mock will talk to the real device.
- [`.github/workflows/ci.yml`](../../.github/workflows/ci.yml) — replays `sample_session.jsonl`
  through the bridge on every push and PR, asserts the expected `dash`
  verbs were emitted.
- Issue templates (bug / feature / question) and PR template under
  [`.github/`](../../.github/), scoped to wire protocol / scenes / hooks.
- [`docs/index.html`](../../docs/index.html) — homepage at
  `https://caldis.github.io/esp32-agent-dashboard/`: hero, terminal
  demo, scene gallery, comparison table, get-started CTA.

## Framework fixes upstreamed

This release pulled in two `esp-harness` fixes that were surfaced by
real-device use:

- **`esp-harness@664b14e`** — tokeniser preserves inner double quotes
  on quote-leading tokens, so nested JSON survives the device's
  command parser. Surfaced as **G-7**.
- **`esp-harness@98affb0`** — `console_protocol` drains the overflow
  tail after a too-long line, so oversize JSON pushes get exactly one
  `ERR:` instead of `ERR:` + spurious `unknown command` for the
  truncated tail.

Both fixes ride along with `v0.1.0`.

## Known limitations

- USB-Serial only. BLE NUS is on the v1.0 roadmap.
- [`docs/demo_inputs.jsonl`](../../docs/demo_inputs.jsonl) uses Claude-Code-hook PascalCase
  event names (`SessionStart`, `UserPromptSubmit`, …); the bridge
  expects snake_case `type:` keys. CI uses
  [`tools/sample_session.jsonl`](../../tools/sample_session.jsonl) which is in the bridge's expected
  shape. Cross-format conversion is tracked in [`HARNESS_GAPS.md`](../../HARNESS_GAPS.md).
- Codex event-type strings are inferred from public Codex behaviour
  and may drift between releases. Tracked in
  [`codex_wrapper.py`](../../tools/codex_wrapper.py).
- Firmware is not built in CI (cross-compiling ESP-IDF on a Linux
  runner is slow and image-fragile). Real-hardware verification
  happens at release time via `tools/smoke.ps1` (planned).
